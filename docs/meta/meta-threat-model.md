# Meta Integration Threat Model

**Document ID:** META-115 | Version 1.0 | Status: Draft for Owner Approval | Phase: 3A (Architecture Finalization)

Extends `docs/identity/identity-threat-model.md`'s established format and
`ai-marketing-manager-gate-6-security-docs/docs/07-security/THREAT_MODEL.md` (SEC-002)'s
already-named Meta-relevant assets/threats to the full 20-item list the governing task
requires. Every control cited already exists as architecture in this document set (not
implemented in code by this phase) — no new control is invented here that isn't already
specified in `meta-oauth.md`, `meta-token-security.md`, `meta-resource-model.md`,
`meta-adapter-contract.md`, `meta-webhooks.md`, or `meta-rate-limits.md`.

## Audit (governing task §18, restated as this document's closing section)

Auditable Meta events (all reuse the existing `AuditEvent` schema per `meta-architecture.md`
§5, no new audit system): connection started, authorization succeeded, authorization failed,
token health changed, account connected, account disconnected, permissions changed, sync
started, sync failed, sync completed, webhook received, provider mutation requested, provider
mutation completed, provider mutation failed, verification failed. **Never log raw Meta
credentials** — restated a final time as the single rule that governs every row in the table
above.
