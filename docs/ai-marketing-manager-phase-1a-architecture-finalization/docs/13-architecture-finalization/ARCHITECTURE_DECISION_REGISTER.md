| 018 | MFA policy | **ACCEPTED 2026-09-05** | Required for `OWNER`/`ADMIN` and any high-risk financial approval (`budget.approve`/`budget.execute`); optional initially for `MANAGER`/`ANALYST`/`VIEWER`. Not implemented during Phase 2A. See `docs/identity/phase-2a-owner-decision-package.md` OD-06. |
| 019 | Membership permission overrides | **DEFERRED — owner-confirmed 2026-09-05** | Role-based authorization only for Phase 2 (`Membership → Role → RolePermissions`); `membership_permission_overrides` stays an unpopulated schema placeholder for future enterprise requirements. See `docs/identity/phase-2a-owner-decision-package.md` OD-05. |
| 020 | Owner invariant and workspace lifecycle | **ACCEPTED 2026-09-05** | A workspace can never have zero owners; owner removal requires either another active owner or a completed ownership transfer, implemented transactionally. Extended by the owner: workspace deletion/closure must be explicitly authorized and audited, and the application must never silently orphan a workspace — both Clerk organization lifecycle and application workspace lifecycle are maintained together. See `docs/identity/phase-2a-owner-decision-package.md` OD-08 and `docs/identity/workspace-model.md` §5. |
| 021 | Identity synchronization and reconciliation baseline | **ACCEPTED 2026-09-05** | Clerk webhooks + periodic reconciliation, baseline every 30 minutes, configurable. Webhook processing authenticated, idempotent, replay-safe, retry-safe, and tolerant of missing/out-of-order delivery — matches the already-accepted design in `docs/identity/identity-sync.md`, with the reconciliation-frequency gap now closed. See `docs/identity/phase-2a-owner-decision-package.md` OD-09. |
| 022 | AI authorization boundary | **Reconfirmed ACCEPTED 2026-09-05** | AI has no standing authorization; every AI tool call re-evaluates the full chain (Authenticated User → Workspace Membership → Permission → Resource Authorization → Action Policy → Financial Policy → Approval) and never selects or expands workspace scope. Already required/non-negotiable per `ADR-002-AI-EXECUTION-BOUNDARY`; this closure formally reconfirms it for the Phase 2A gate, no design change. See `docs/identity/phase-2a-owner-decision-package.md` §5. |
| 023 | Worker authorization context | **ACCEPTED 2026-09-05** | Privileged jobs must carry, as applicable: `workspaceId`, `initiatingUserId`/actor identity, resource scope, action scope, `correlationId`, `jobId`. Workers must never accept arbitrary client-controlled authorization context. See `docs/identity/phase-2a-owner-decision-package.md` §6. |
| 024 | Active workspace resolution chain | **ACCEPTED 2026-09-05** | `Authenticated Clerk user → Clerk organization context → Application membership → Workspace status → Authorized workspace`; a client-supplied workspace ID is never trusted without this chain running in full. Refines, does not replace, `docs/identity/workspace-model.md` §3 — `requireMembership()` still re-verifies against our database on every request. See `docs/identity/phase-2a-owner-decision-package.md` OD-11. |
